# مرجع API

> ⚠️ **یادداشت داخلی (قبل از انتشار حذف شود):** هر جا ⚠️ هست یعنی هنوز روی API واقعی تأیید نشده.

**آدرس پایه:** `https://api.intelligence.sotoon.ir/inference/v1`
**احراز هویت:** هدر `Authorization: Bearer کلید-شما`

| اندپوینت | کاربرد |
|---|---|
| `GET /models` | لیست مدل‌ها |
| `POST /chat/completions` | گفتگو با مدل (پرکاربردترین) |
| `POST /embeddings` | تبدیل متن به بردار |
| `POST /messages` | قالب Anthropic (برای Claude Code) |
| `POST /responses` ⚠️ | قالب Responses شرکت OpenAI (تأیید نشده) |
| تولید تصویر ⚠️ | فعلاً در دست بررسی است |

---

## مدل‌ها

`GET /models` فقط شناسه‌ی مدل‌ها را می‌دهد:

```json
{ "data": [ { "id": "provider/model-name", "object": "model" } ] }
```

- شناسه را دقیقاً همان‌طور که برگشته در فیلد `model` بنویسید.
- لیست به کلید شما بستگی دارد.
- قیمت، اندازه‌ی context و نوع ورودی (متن، تصویر، صدا) در صفحه‌ی **مدل‌ها** در داشبورد است. فیلد `owned_by` معنای خاصی ندارد.

### لیست مدل‌ها هر روز ممکن است تغییر کند

مدل‌ها هر روز اضافه و کم می‌شوند و اسم بعضی‌شان نسخه یا تاریخ دارد و عوض می‌شود. پس:

- اسم مدل را در کد ثابت نگذارید. آن را در تنظیمات نگه دارید و قبل از استفاده بررسی کنید که هنوز در لیست هست:

```python
models = {m.id for m in client.models.list().data}
if "MODEL_ID" not in models:
    print("این مدل دیگر در لیست نیست؛ یک مدل دیگر انتخاب کنید.")
```

- اگر مدلی حذف شده باشد، با خطای `400 Invalid model name` روبه‌رو می‌شوید.
- ابزارهایی که لیست مدل‌ها را خودکار نمی‌گیرند (Claude Code، OpenCode، Cursor، Codex، Copilot)، هر چند وقت یک‌بار لیست خودتان را با صفحه‌ی **مدل‌ها** مقایسه کنید.

## گفتگو (Chat Completions)

`POST /chat/completions`

| پارامتر | توضیح |
|---|---|
| `model` (الزامی) | شناسه‌ی مدل |
| `messages` (الزامی) | لیست پیام‌ها با `role` (`system`، `user`، `assistant`، `tool`) و `content` |
| `stream` | با `true` پاسخ زنده می‌گیرید |
| `max_tokens` | سقف توکن پاسخ (به بخش «پاسخ خالی» توجه کنید) |
| `temperature` | میزان خلاقیت. ⚠️ *بازه‌ی مجاز بسته به مدل فرق می‌کند.* |
| `tools`، `tool_choice` | فراخوانی ابزار (پایین‌تر) |

پارامترهای دیگر مثل مستندات OpenAI کار می‌کنند.

**پاسخ:**

| فیلد | معنی |
|---|---|
| `choices[0].message.content` | متن پاسخ |
| `choices[0].finish_reason` | `stop` (تمام شد)، `length` (به سقف توکن رسید)، `tool_calls` (مدل ابزار خواسته) |
| `usage` | توکن‌های ورودی، خروجی و کل. هزینه بر اساس همین حساب می‌شود. |
| `model` | نسخه‌ی دقیق مدل. ممکن است کمی با چیزی که فرستادید فرق داشته باشد. |

### پاسخ خالی

مدل‌های reasoning قبل از جواب «فکر می‌کنند» و توکن‌های تفکر هم از `max_tokens` کم می‌شود. اگر سقف کوچک باشد، همه‌اش صرف تفکر می‌شود و `content` خالی برمی‌گردد و `finish_reason` برابر `length` است. `max_tokens` را بزرگ‌تر کنید یا ننویسید. تعداد توکن‌های تفکر در `usage.completion_tokens_details.reasoning_tokens` است.

### کنترل میزان تفکر ⚠️

نام پارامتر بسته به سازنده‌ی مدل فرق دارد: برای مدل‌های OpenAI `"reasoning_effort": "low"` (یا `medium`، `high`) و برای بقیه `"reasoning": { "effort": "low" }`. اگر مدل reasoning نداشته باشد، خطای ۴۰۰ می‌گیرید. *هر دو فرمت هنوز تست نشده‌اند.*

### پاسخ زنده (Streaming)

با `"stream": true` پاسخ تکه‌تکه می‌رسد. کتابخانه‌ی OpenAI خودش این را مدیریت می‌کند و متن هر تکه در `choices[0].delta.content` است:

```python
stream = client.chat.completions.create(
    model="MODEL_ID",
    messages=[{"role": "user", "content": "یک داستان کوتاه بنویس."}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

## فراخوانی ابزار (Tool Calling)

به مدل می‌گویید چه تابع‌هایی دارید. مدل تصمیم می‌گیرد کدام را با چه ورودی‌ای صدا بزند. **اجرای تابع با کد شماست.**

۱. ابزار را در `tools` تعریف کنید:

```json
{
  "model": "MODEL_ID",
  "messages": [{ "role": "user", "content": "هوای تهران چطوره؟" }],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "هوای یک شهر را برمی‌گرداند",
      "parameters": {
        "type": "object",
        "properties": { "city": { "type": "string" } },
        "required": ["city"]
      }
    }
  }]
}
```

۲. اگر مدل ابزار خواست، `finish_reason` برابر `tool_calls` است. `arguments` یک **رشته‌ی JSON** است و باید parse شود:

```json
"tool_calls": [{ "id": "call_abc123", "type": "function",
  "function": { "name": "get_weather", "arguments": "{\"city\":\"Tehran\"}" } }]
```

۳. تابع را اجرا کنید و نتیجه را با نقش `tool` برگردانید. همه‌ی `messages` را دوباره بفرستید تا مدل جواب نهایی را بنویسد:

```json
{ "role": "assistant", "content": null, "tool_calls": [ ...همان بالا... ] },
{ "role": "tool", "tool_call_id": "call_abc123", "content": "۲۸ درجه، آفتابی" }
```

همه‌ی مدل‌ها ابزار را پشتیبانی نمی‌کنند. ⚠️ *نیاز به تأیید: آیا مشخصات مدل در داشبورد پشتیبانی از ابزار را نشان می‌دهد؟*

## Embeddings

`POST /embeddings` متن را به بردار عددی تبدیل می‌کند (جستجوی معنایی، RAG). مدل‌های embedding در همان `/models` هستند. مدل گفتگو را برای embedding به کار نبرید.

```bash
curl https://api.intelligence.sotoon.ir/inference/v1/embeddings \
  -H "Authorization: Bearer $SOTOON_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "model": "EMBEDDING_MODEL_ID", "input": "سلام دنیا" }'
```

بردار در `data[0].embedding` است.

## قالب Anthropic

`POST /messages` با **همه‌ی مدل‌ها** کار می‌کند، نه فقط Claude. `max_tokens` در این قالب الزامی و پاسخ در `content[0].text` است.

```bash
curl https://api.intelligence.sotoon.ir/inference/v1/messages \
  -H "Authorization: Bearer $SOTOON_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{ "model": "MODEL_ID", "max_tokens": 1024,
        "messages": [{ "role": "user", "content": "سلام!" }] }'
```

## خطاها

همه‌ی خطاها این قالب را دارند. `code` یک **رشته** است، نه عدد:

```json
{ "error": { "message": "...", "type": "...", "param": "...", "code": "400" } }
```

| کد | دلیل رایج | چه کنم؟ |
|---|---|---|
| `401` | کلید اشتباه یا باطل شده | کلید را دوباره کپی کنید. بعد از `Bearer` یک فاصله باشد. |
| `400` با `Invalid model name` | اسم مدل غلط است یا کلید شما به آن دسترسی ندارد | لیست مدل‌ها را دوباره بگیرید و اسم را دقیقاً کپی کنید. |
| `429` ⚠️ | تعداد درخواست‌ها زیاد است | با فاصله‌ی رو به افزایش (۱، ۲، ۴ ثانیه...) دوباره بفرستید. *قالب دقیق تأیید نشده.* |
| ⚠️ | بودجه‌ی شما تمام شده | در صفحه‌ی «مصرف» افزایش دهید. *کد و پیام دقیق تأیید نشده.* |
| `5xx` | خطای موقت سرور یا ارائه‌دهنده‌ی مدل | با فاصله‌ی رو به افزایش دوباره بفرستید. |
| بدون پاسخ | مشکل اتصال | اینترنت و VPN را بررسی کنید. در `curl` گزینه‌ی `--max-time 60` بگذارید. |

برای `400` و `401` تکرار درخواست فایده ندارد.

## قیمت‌گذاری و هزینه

- **پرداخت بر اساس مصرف:** هزینه بر اساس تعداد **توکن‌های مصرفی** حساب می‌شود، نه تعداد درخواست. هزینه‌ی ثابت یا اشتراک ندارد و برای API، چت و ابزارهای کدنویسی یکسان است.
- **قیمت هر مدل را کجا ببینم؟** در صفحه‌ی **مدل‌ها**. قیمت توکن ورودی و خروجی هر مدل آنجاست و از مدلی به مدل دیگر فرق می‌کند.
- **تعداد توکن‌ها را از کجا بدانم؟** فیلد `usage` در هر پاسخ.

```
هزینه = (توکن ورودی ÷ 1,000,000 × قیمت ورودی) + (توکن خروجی ÷ 1,000,000 × قیمت خروجی)
```

**مثال** (اعداد فرضی): قیمت ورودی ۵ دلار و قیمت خروجی ۱۵ دلار به ازای یک میلیون توکن. اگر ۱٬۰۰۰ توکن ورودی و ۵۰۰ توکن خروجی مصرف شود:

```
(1,000 ÷ 1,000,000 × 5) + (500 ÷ 1,000,000 × 15) = 0.0125 دلار
```

**مدل‌های reasoning:** توکن‌های «تفکر» جزو توکن‌های خروجی (`completion_tokens`) شمرده می‌شوند، پس یک پاسخ کوتاه هم می‌تواند خروجی بیشتری از انتظار مصرف کند. ⚠️ *تأیید نهایی نحوه‌ی محاسبه‌ی هزینه‌ی reasoning و cache از تیم فنی.*

### بودجه و پرداخت (شرایط فعلی)

> این شرایط وضعیت فعلی است و ممکن است در آینده تغییر کند.

- **بودجه‌ی اولیه:** با ساخت حساب، **۵ دلار** بودجه‌ی اولیه به شما اختصاص داده می‌شود. مصرف شما از این بودجه کم می‌شود.
- **افزایش بودجه:** هر زمان لازم شد، از صفحه‌ی **مصرف** (دکمه‌ی «افزایش بودجه») بودجه را بیشتر کنید. در هر روز حداکثر **۸۰ دلار** می‌توانید بودجه را افزایش دهید.
- **پرداخت:** فقط به اندازه‌ی **مصرف واقعی** پرداخت می‌کنید. در روز **۲۳ هر ماه** فاکتور مصرف صادر می‌شود و **۱۰٪ مالیات بر ارزش افزوده** به آن اضافه می‌شود.
- **پیگیری مصرف:** در صفحه‌ی **مصرف** تعداد درخواست، توکن، هزینه و روند روزانه‌ی ۷ یا ۳۰ روز گذشته را می‌بینید.

⚠️ *نیاز به تأیید: تقویم ماه (شمسی یا میلادی) و بازه‌ی مصرفِ هر فاکتور، واحد پول فاکتور، بودجه برای هر workspace است یا کل حساب، و اینکه وقتی بودجه تمام می‌شود API دقیقاً چه خطایی برمی‌گرداند.*

**چطور هزینه را کم کنم؟**

1. برای کارهای ساده از مدل‌های کوچک‌تر و ارزان‌تر استفاده کنید.
2. با `max_tokens` طول پاسخ را محدود کنید (برای مدل‌های reasoning عدد را خیلی کوچک نگذارید؛ به بخش «پاسخ خالی» نگاه کنید).
3. پرامپت‌های شفاف و کوتاه بنویسید؛ توکن کمتری مصرف می‌کنند.
4. مصرف را مرتب در صفحه‌ی **مصرف** ببینید.

## محدودیت‌ها ⚠️

- **حداکثر درخواست و توکن در دقیقه:** *نیاز به تأیید از تیم*
- **حداکثر اندازه‌ی ورودی (context):** برای هر مدل فرق دارد و در صفحه‌ی **مدل‌ها** است.
