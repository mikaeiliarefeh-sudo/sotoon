## ۱. صورت‌حساب و شمارش توکن (cache)

**چرا مهم است:** یک مشتری (پاتوق) گفته ما توکن را بیشتر از واقعیت می‌شماریم. او از Claude و Bedrock استفاده می‌کرد. اگر هزینه برای توکن‌های cache گران‌تر از واقع حساب شود، از مشتری بیشتر می‌گیریم.

**آنچه می‌دانیم:**
- تعداد توکن مصرفی هر مشتری را از **LiteLLM** می‌خوانیم.
- LiteLLM برای هر مشتری یک **هزینه** هم نگه می‌دارد.
- در داشبورد مشتری، **تعداد توکن** نمایش داده می‌شود (و هزینه).
- LiteLLM قیمت cache را جدا حساب می‌کند **اگر** در تعریف مدل `cache_read_input_token_cost` و `cache_creation_input_token_cost` تنظیم شده باشد. اسکریپت `fetch_openrouter_models.py` این‌ها را فقط وقتی تنظیم می‌کند که OpenRouter قیمت `input_cache_read` / `input_cache_write` داده باشد (و ۱۵٪ مارجین هم روی آن‌ها اعمال می‌شود).

**آنچه نمی‌دانیم (باید روشن شود):**
1. هزینه‌ای که مشتری در پنل می‌بیند از کجا می‌آید؟
   - **الف)** مستقیم از هزینه‌ی ثبت‌شده در LiteLLM ← مشکلی نیست (اگر cache درست تنظیم شده باشد).
   - **ب)** از فرمول خودمان: `قیمت هر میلیون توکن × تعداد توکن` ← اگر تعداد توکن شامل توکن‌های cache باشد، همه با قیمت کامل حساب می‌شوند و **بیش‌حساب** است.
2. «تعداد توکن» پنل، توکن‌های cache را هم داخل ورودی می‌شمارد؟

**فرضیه‌ها (تأییدنشده، از روی کد ندیده‌ام):**
- **شمارش:** LiteLLM `prompt_tokens` را معمولاً با جمع توکن‌های ورودی + cache می‌سازد. در کنسول خود Anthropic/Bedrock، `input_tokens` معمولاً جدا از توکن‌های cache نمایش داده می‌شود. پس مشتری عدد کمتری در کنسول آن‌ها می‌بیند و ما بیشتر. Claude Code و ابزارهای مشابه خیلی از cache استفاده می‌کنند، پس اختلاف بزرگ می‌شود.
- **مبلغ:** برای مدل‌هایی که قیمت cache در تعریفشان تنظیم نشده (یا مدل‌های OpenAI مستقیم که از اسکریپت OpenRouter نمی‌آیند)، توکن cache با قیمت کامل ورودی حساب می‌شود.

**راه تحقیق (سه‌طرفه):** برای یک مشتری و یک روز، سه عدد را کنار هم بگذارید:

| منبع | چه چیزی |
|---|---|
| ۱. لاگ خرج LiteLLM (Spend Logs) | `prompt_tokens`، توکن cache، `completion_tokens`، `spend` به‌ازای هر درخواست |
| ۲. پنل مشتری | همان روز: توکن و هزینه |
| ۳. محاسبه‌ی دستی | `(ورودی غیر cache × قیمت ورودی) + (خوانش cache × قیمت cache read) + (نوشتن cache × قیمت cache write) + (خروجی × قیمت خروجی)` با قیمت ما |

- اگر ۱ ≠ ۲: پنل خودش جدا حساب می‌کند.
- اگر ۱ ≠ ۳: LiteLLM قیمت cache را برای آن مدل ندارد یا غلط دارد.
- توکن پنل را با کنسول خود Anthropic/Bedrock برای همان بازه مقایسه کنید.
- مشتری پاتوق: با خودش هماهنگ کنید که یک روز مشخص و مدل مشخص را بررسی کنیم.

**آزمایش سریع (۱۰ دقیقه، با `curl`):** دو بار یک درخواست بلند یکسان به یک مدل OpenAI بفرستید و در پاسخ ببینید `cached_tokens` و هدر `x-litellm-response-cost` بار دوم کمتر می‌شود یا نه:

```bash
LONG=$(yes "Sotoon cache test sentence number one." | head -n 400 | tr '\n' ' ')
for i in 1 2; do
  curl -s -D /tmp/h$i.txt -o /tmp/b$i.json https://api.intelligence.sotoon.ir/inference/v1/chat/completions \
    -H "Authorization: Bearer $SOTOON_API_KEY" -H "Content-Type: application/json" \
    -d "{\"model\":\"openai/gpt-5-nano\",\"max_tokens\":200,\"messages\":[{\"role\":\"user\",\"content\":\"$LONG Say hi.\"}]}"
  echo "--- call $i"; grep -i 'x-litellm-response-cost' /tmp/h$i.txt
  python3 -c "import json,sys;print(json.load(open(sys.argv[1]))['usage'])" /tmp/b$i.json
  sleep 5
done
```

- بار دوم باید `prompt_tokens_details.cached_tokens` بزرگ‌تر از صفر داشته باشد (cache خودکار OpenAI).
- اگر هزینه‌ی بار دوم در هدر **کمتر** شد، LiteLLM تخفیف cache را اعمال می‌کند. اگر **برابر** ماند، تخفیف اعمال نمی‌شود.
- بعد در پنل مشتری ببینید توکن همان دو درخواست چقدر اضافه شده و هزینه چقدر.

**نتیجه‌ی احتمالی و اقدام:**
- پنل هزینه را از LiteLLM می‌خواند و تخفیف cache درست است ← فقط برای مشتری توضیح دهیم «توکن cache هم شمرده می‌شود ولی ارزان‌تر حساب می‌شود»، و در پنل توکن را به ورودی، cache و خروجی تفکیک کنیم.
- هزینه با فرمول خودمان حساب می‌شود یا قیمت cache تنظیم نشده ← **اصلاح فوری** و در صورت بیش‌حساب بودن، تسویه با مشتریان.

## ۲. Claude Code با مدل‌های OpenAI مستقیم

- خطا: `400 Unknown parameter: 'output_config'` (قبلش `context_management`). Claude Code فیلدهای مخصوص Anthropic می‌فرستد.
- مدل‌های OpenRouter (مثل `bytedance-seed/seed-1.6-flash`) این فیلدها را می‌پذیرند و بی‌صدا حذف می‌کنند؛ مدل‌های OpenAI مستقیم (مثل `openai/gpt-5-nano`) ردشان می‌کنند.
- `drop_params: true` فقط پارامترهای شناخته‌شده‌ی OpenAI را حذف می‌کند. برای فیلدهای ناشناخته احتمالاً `additional_drop_params: ["output_config","context_management"]` لازم است. ⚠️ *کیارش تأیید کند.*
- نگرانی کیارش درست است: `drop_params` سراسری ممکن است پارامترهای مهم مشتری (مثلاً `tools`، `response_format`) را بی‌صدا حذف کند. حذف فقط فیلدهای مشخص امن‌تر است.
- نمونه‌ی تکرار در `docs-tools` / پیام تیم موجود است.
