# پیام آماده برای گروه شرکت: تست مصرف، توکن و هزینه

(نسخه‌ی کامل در `team-brief-billing.md`؛ جزئیات و شناسه‌ها در `open-issues.md`)

محدوده: فقط Claude Opus 4.6 از مسیر OpenRouter.

## درست کار می‌کند
- شمارش توکن: پنل = لاگ LiteLLM = اوپن‌روتر.
- هزینه‌ی cache: خواندن ≈۹۰٪ ارزان‌تر، نوشتن ≈۲۵٪ گران‌تر، مطابق اوپن‌روتر.
- هر دو مسیر `/chat/completions` و `/messages` مبلغ یکسان ثبت می‌کنند.

## مشکلات هزینه
1. (P0) مارجین ۱۵٪ در مبلغ مشتری نیست (۵۴٬۰۱۶ توکن: باید ۰.۳۱۰۷ می‌شد، ثبت ۰.۲۷۰۲). قیمت cache در تعریف مدل هم بدون مارجین است. اصلاح یعنی ≈۱۵٪ افزایش هزینه‌ی مشتری ← تصمیم محصول/مالی.
2. (P2) هدر `x-litellm-response-cost-original` در `/v1/messages` گمراه‌کننده است.

- (سؤال) مارجین ۱۵٪ در مرحله‌ی فاکتور ریالی اعمال می‌شود؟ پنل با لاگ LiteLLM قبل/بعد برابر است (۰.۶۸ در برابر ۰.۶۸۰۳؛ با ۱۵٪ ۰.۷۸ می‌شد)؛ برای راستی‌آزمایی یک فاکتور واقعی را با مجموع دلاری پنل همان بازه مقایسه کنید.

## مشکلات پنل
- توکن‌ها تفکیک ندارند (ورودی + cache + خروجی یک عدد).
- مصرف روزانه به‌ازای هر کلید قابل فیلتر نیست.
- قیمت cache در صفحه‌ی مدل‌ها نیست.
- سؤال: مقیاس `x-litellm-key-spend` (۷.۷–۸.۱$) در برابر پنل (۱.۰۹$ برای ۷ روز).

## مشکلات Claude Code و API (خلاصه)
- باز: `400 Unknown parameter: 'output_config'` روی مدل‌های OpenAI مستقیم (P0).
- حل‌شده: `context_management` (با `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`)، صفحه‌ی ورود (env + `disableLoginPrompt`).
- داکیومنت: لیست مدل دستی، نوار مدل، هویت مدل، وب/Slack/دسکتاپ، فاش شدن کلید در `settings.json`.
- تصمیم حقوقی/محصول: مدل غیر Claude در Claude Code و کشورهای مجاز Anthropic.
